# 江东小乔

## 防破解部分

### 1.版本更新

1. 软件启动的时候，会自动从服务器获取最新的辅助脚本，具体流程如下：
    * 首先获取启动码
        * 软件启动的时候，首先向服务器提交（机器码、随机数、校验值）获取启动码；
        * 其中机器码用于唯一标识用户的电脑；
        * 随机数为了让服务器防止有人重复执行该请求（尤其是为了防止有人抓包后重复发送）；
        * 校验值为了防止有人伪造该请求；
        * 服务器校验通过后，返回启动码；
        * 这个过程中，无需担心有人伪造服务器反馈，因为反馈的启动码毫无意义；
    * 然后获取辅助脚本
        * 向服务器请求数据的时候，将带上启动码；
        * 服务器校验启动码之后，返回实际执行的脚本；
        * 软件解密脚本并放到内存中；
    * 这个过程如果失败了，软件直接提示用户并退出；
2. 软件从启动之后，每隔1个小时，会向服务器请求脚本
    * 软件内存中的脚本，存放超过3小时则自动清空
    * 这样，能保证软件内存中的脚本必定能保证更新
    * 通过这样的策略，防止服务器版本更新之后，用户通过技术手段禁止软件继续访问服务器，从而让本地脚本不能得到更新；
3. 用户每次点击重新载入的时候，将自动从内存中载入最近一次更新的脚本
    * 软件UI上，我会让开始按钮点击之后变灰，即便断开也不恢复，这样，如果用户想要重新开始挂机，就必须重新载入；
    * 这样，如果用户想要开始挂机，必定需要重新从内存中载入最新脚本
    * 如果某个用户挂机之后，一直不上游戏，而且游戏连接一直稳定，那他可以一直使用老版本挂下去；
4. 软件功能更新
    * 服务器更新脚本之后，软件会在一个小时之内，自动获得新版本；
    * 用户在下一次点击重新载入的时候，新版本会生效；
    * 如果服务器关闭，所有玩家的软件将在3个小时之后，内存中脚本失效；
    * 内存中脚本失效之后，玩家在下一次点击重新载入的时候，软件就不再可用。
    
### 2. 服务器指令交互防破解

1. 软件发给服务器的指令
    * 发给服务器的指令，将会带上如下内容：
        * 启动码，这是软件启动时候获取的启动码，服务器将根据该码来判断用户身份，并进行基础的身份校验；
        * 用户命令内容，这是需要发给服务器的交互内容，此部分不校验防伪；
        * 时间戳，发送命令的服务器的本地时间戳，服务器将根据这个字段来判断是否重复请求；
        * hash值，该值为前面所有项的某个hash值，目的是为了校验前面的字段是否我们的软件生成的；
2. 服务器返回的指令
    * 服务器的处理：
        * 服务器首先计算hash值，hash值校验失败，则该指令为伪造；
        * 服务器将该指令的时间戳和上一次指令的时间戳进行校验，如果该时间戳不大于上次时间戳，那么该指令为伪造；
        * 通过校验之后，正常处理业务逻辑；
    * 服务器的反馈，将会带上如下内容：
        * 用户业务反馈信息；
        * 发送者hash值，这是用户请求时带来的hash值，原路返回；
        * 服务器反馈的hash值，该值为前面所有字段的hash；
3. 软件对服务器反馈的处理
    * 软件检查反馈的hash值，是否为自己发出去的那个，如果不是，不予处理；
    * 软件计算反馈指令的hash值，看指令是否伪造；
    * 校验成功之后，正常处理业务逻辑；
    
### 3. 用户功能限制

1. 用户每次点击开始的时候，发送服务器指令，获取该用户的vip身份
    * 发送的数据有：userId，roleId
    * 反馈的数据有：vip等级
2. 成功获得用户的vip信息之后，进入正常挂机
    * 软件根据vip信息，进行相关功能限制。
